# Setup Guide Template

Use this template when contributing a new setup guide to OpenSetup.

The goal is to create guides that are:

- Beginner-friendly
- Practical and actionable
- Easy to follow
- Focused on setup rather than theory
- Consistent with existing OpenSetup documentation

---

# Guide Title

```md
# <Technology Name> Setup Guide
```

Add a short one-line description explaining what the user will achieve.

Example:

```md
Set up a modern React application powered by Vite and TypeScript in just a few minutes.
```

---

## Prerequisites

List everything required before starting.

Example:

```md
## Prerequisites

Before starting, make sure you have:

- Node.js installed
- npm installed
- A code editor (VS Code recommended)
```

If applicable, include verification commands.

---

## Step 1: <First Setup Step>

Explain the first action clearly.

Include commands, expected prompts, and expected results.

---

## Step 2: <Second Setup Step>

Continue with the next action.

Add a brief explanation if needed.

---

## Step 3: <Additional Setup Steps>

Continue the setup process using numbered steps.

Each step should:

- Have a clear title
- Include commands where necessary
- Explain expected results
- Avoid unnecessary theory

---

## Verification

Include a verification step whenever possible.

The user should know how to confirm the setup worked successfully.

---

## Project Structure

If the technology creates a project structure, include it.

Only include folders and files that are important for beginners.

---

## Important Files or Folders

If applicable, explain the key files users will work with.

Keep explanations short and practical.

---

## Common Commands (Optional)

Include commonly used commands when useful.

---

## Troubleshooting (Optional)

Add troubleshooting only if users commonly encounter issues.

Keep solutions concise.

---

## Installation Complete

End every guide with a completion section.

Example:

```md
## Installation Complete

Your setup is now complete.

You can now start building:

- Projects
- Applications
- APIs
- Automations
- Workflows
```

---

# Writing Guidelines

### Keep It Practical

Focus on:

- What to do
- Which command to run
- What to expect

Avoid long theoretical explanations.

---

### Use Clear Headings

Use:

```md
## Step 1:
## Step 2:
## Step 3:
```

instead of large unstructured paragraphs.

---

### Explain Commands

Never assume beginners know what a command does.

Provide a short explanation when necessary.

---

### Show Expected Results

Whenever possible, include:

- Example output
- Verification steps

---

### Keep Structure Consistent

Most OpenSetup guides should follow:

```text
Title
Description
Prerequisites
Step 1
Step 2
Step 3
Verification
Project Structure (Optional)
Important Files (Optional)
Common Commands (Optional)
Troubleshooting (Optional)
Installation Complete
```
---

### Avoid

- Excessive theory
- Large architecture deep-dives
- Vendor marketing language
- Unnecessary jargon
- Huge walls of text

The goal is to help contributors create setup guides that are concise, practical, and consistent across OpenSetup.
